## 二、 关系类型规范

为了让前端能够根据不同的连线类型渲染出不同的 UI 组件（例如：对前置依赖标红，对计算工具一键跳转，对报警进行紧急高亮），我们制定了以下 10 种标准的图谱关系类型：

1.  **prerequisite (前置知识)**
    *   *定义*：学习或执行该操作前，必须掌握的前置理论或安全规范。
    *   *适用场景*：对刀之前必须回零；长度偏置前必须建立工件坐标系。
    *   *示例边*：`machine-home-return` -> `machine-tool-setting`
2.  **next (下一步学习)**
    *   *定义*：基于当前知识点推荐的后续最优学习节点。
    *   *适用场景*：圆弧插补完成后推荐进给方式或程序仿真。
    *   *示例边*：`calc-radius-diameter` -> `learn-program-structure`
3.  **related (相关知识)**
    *   *定义*：概念上的横向关联，非强制依赖但有利于拓宽知识结构。
    *   *适用场景*：G54 坐标系与 G53 机床坐标系的对比参考。
    *   *示例边*：`learn-g54-g59` -> `g53-machine-coordinate`
4.  **risk (共同风险)**
    *   *定义*：可能导致断刀、撞机、伺服过载或报废工件的强关联动作。
    *   *适用场景*：冷却不力与极限开关超程/断刀的关联。
    *   *示例边* Nic：`m08-m09-coolant` -> `fault-limit-switch`
5.  **tool (关联工具)**
    *   *定义*：该知识点可直接调用的物理计算器或速查表。
    *   *适用场景*：丝锥攻丝与冷却液开启、进给换算器的对接。
    *   *示例边*：`tool-thread-tap` -> `m08-m09-coolant`
6.  **compare (易混对比)**
    *   *定义*：字面相似但物理意义截然相反的指令或工艺。
    *   *适用场景*：顺铣与逆铣；G90（绝对）与 G91（增量）的对比。
    *   *示例边*：`material-carbon-steel` -> `material-aluminum`
7.  **operation (操作流程关联)**
    *   *定义*：在机床操作面板上具有前后承接的操作步骤。
    *   *适用场景*：试切对刀测得的绝对坐标值，手工存入坐标系寄存器中。
    *   *示例边*：`machine-tool-setting` -> `learn-g54-g59`
8.  **parameter (参数计算关联)**
    *   *定义*：公式变量之间的数学计算与传递关系。
    *   *适用场景*：刀具直径与线速度 Vc 共同推导主轴转速 S。
    *   *示例边*：`tool-drill-selection` -> `calc-vc-rpm`
9.  **alarm (报警故障关联)**
    *   *定义*：由特定的异常操作引发的机床系统报警信息。
    *   *适用场景*：超程限位触发 5136 或 SV0438 伺服报警。
    *   *示例边*：`quick-fanuc-alarm` -> `fanuc-alarm-common`
10. **case (加工案例关联)**
    *   *定义*：理论指令在真实物理零件加工中的具体实例应用。
    *   *适用场景*：刀具半径补偿在法兰盘或精密齿轮粗/精车削中的应用。
    *   *示例边*：`g40-cancel-comp` -> `process-allowance-basics`

## 三、 六大核心知识链路设计

### 3.1 坐标系链路 (回零 -> 对刀 -> G54 -> G43 -> 程序检查)
*   **面向用户**：零基础小白、刚进厂操机学员。
*   **排序原因**：开机后首先回机械参考点建立系统的绝对参考物，然后进行对刀测出工件偏差，接着将数值录入 G54 建立工件原点，随后调用 G43 读入刀长补偿防止撞刀，最后对程序进行静态复核。
*   **详情页推荐**：在 G54 页面的“前置依赖”中引入“对刀操作”，在“推荐后续”中指向“G43 长度补偿”。
*   **学习地图引导**：以时间轴节点引导，前一节点未打卡解锁时，后续卡片呈灰色不可点状态。

### 3.2 刀补链路 (刀具选择 -> G41/G42 -> G40 -> 首件检查)
*   **面向用户**：铣床与加工中心编程工程师、中级操机工。
*   **排序原因**：基于所选刀具的几何尺寸，在进入工件切削前建立半径补偿（G41/G42），加工完毕后必须使用 G40 退出刀补以防过切，退出后立即停机进行首件量测，控制余量。
*   **详情页推荐**：置顶红框展示“G40 取消刀补防撞关键点”，并关联余量控制页。
*   **学习地图引导**：设计“顺铣/逆铣”手掌判别交互游戏，选对后再激活 G41。

### 3.3 圆弧链路 (G17/G18/G19 -> G02/G03 -> 半径/IJK -> 模拟检查)
*   **面向用户**：CNC 铣削编程员、CAM 软件应用者。
*   **排序原因**：首先选定加工平面（平面决定了圆弧投影轴），然后指定走向 G02 或 G03，接着使用 R 或 I/K 变量指定圆心，最后使用系统校验器进行轨迹模拟。
*   **详情页推荐**：右侧展示 G17/G18/G19 坐标轴对应示意图，并关联半径直径换算器。
*   **学习地图引导**：用动态 GIF 轨迹图演示 I/K 矢量指向，解开新手混淆。

### 3.4 钻孔链路 (G81 -> G83 -> G84 -> 冷却/排屑 -> 断刀风险)
*   **面向用户**：车间现场操机组长、工艺优化师。
*   **排序原因**：普通钻孔（G81）与啄钻（G83）是孔加工前置步骤，攻丝（G84）是后置终点，攻丝时必须选对丝锥排屑槽并开启大压力冷却，否则会导致扭矩过载崩刃断刀。
*   **详情页推荐**：攻丝详情页直接关联“底孔速查表”与“转速进给换算器”。
*   **学习地图引导**：三步分步剖面图展示啄钻“进-退-进”轨迹，打卡答题解锁。

### 3.5 参数链路 (材料 -> 刀具 -> 线速度 -> 转速 -> 进给 -> 粗糙度)
*   **面向用户**：工艺工程师、编程员、模具车间技术员。
*   **排序原因**：根据工件材质硬度选定刀具材质与几何参数，然后查表获取推荐线速度 Vc，利用直径求出转速 S，结合齿数算得进给 F，以此进给速度走刀以达到要求的粗糙度。
*   **详情页推荐**：在铝合金或钢件参数页中直接内嵌转速进给换算器，实现数值同步传递。
*   **学习地图引导**：以“铁屑形状判断参数对错”的仪表盘滑块交互形式展示参数联动。

### 3.6 报警链路 (报警代码 -> 原因 -> 检查项 -> 维修建议)
*   **面向用户**：车间维修电工、设备科长、夜班操机骨干。
*   **排序原因**：一旦出现报警代号（如 SV0438），先分类定位是伺服系统还是限位，然后进行物理碰块排查，最后给出超程释放等维修动作建议。
*   **详情页推荐**：在报警代码页底端放置“现场快速三步超程释放动作卡”。
*   **学习地图引导**：采用情景插画展示强电柜和碰块释放手轮的物理结构。

## 四、 图谱驱动产品能力设计 (零代码修改方案)

为在不改动 HTML/JS 代码逻辑的情况下将图谱注入产品，我们设计了以下无感桥接方案：

### 4.1 详情页智能推荐对接
*   *方案*：前端的 `ui-recommendations.js` 在渲染详情页（`detail-panel`）的“延伸推荐”时，直接读取 `knowledge_graph.json` 中的 `edges`。
*   *策略*：优先推荐 `type === "prerequisite"`（前置）和 `type === "risk"`（高危风险）的关联 ID。如果相关连线少于 3 条，则降级推荐 `type === "related"` 的 Sibling 节点。

### 4.2 学习路径解锁依赖
*   *方案*：学习地图页面在加载路线卡片时，通过 `prerequisite` 连接线查找该卡片的前置依赖节点。
*   *策略*：若前置节点的 `id` 尚未在 LocalStorage 中的 `completed_tasks` 数组中记录，则直接在卡片上追加 `disabled` 类名，禁用点击，并在卡片悬浮状态下读取边的 `reason` 属性展示为 Tooltip（例如：`“需先通过 回零操作 关卡以掌握基准”`）。

### 4.3 搜索结果排序增强
*   *方案*：搜索框输入关键字时，在完成匹配后，前端通过读取 `knowledge_graph.json` 对结果集进行重排。
*   *策略*：若匹配结果包含 `core: true` 的节点，则赋予其双倍的权重因子（Weight Factor）置顶展示；对于多匹配结果，优先展示图谱中度数（Degree Centrality，即连线边数最多）的枢纽节点，减少偏僻小词对搜索干扰。

### 4.4 AI 助手交互关联
*   *方案*：网页端 AI 侧边栏助手在回答用户数控提问时，可以异步载入 `knowledge_graph.json` 的边关系。
*   *策略*：在回复用户时，自动提取当前主题周边的 links，并在回复末尾自动追问或提供快捷锚点链接（例如：“建议您同时了解与其有【操作承接关系】的 **G43刀长补偿**，点击此处可快速查看防撞安全检查项”）。

### 4.5 自动生成候选边规则 (后续数据导入)
*   *方案*：后续增量导入新的文本知识点时，采用基于**分类继承**和**文本标签共现**的启发式规则。
*   *策略*：
    1.  如果新条目的 `tags` 与图谱中已有节点的 `tags` 重合数大于等于 3 个，则自动生成一条 `type: "related"` 的候选边；
    2.  如果新条目属于 `常用代码` 且包含特定轴向代号，则默认将其 predecessor 节点的边类别设为 `prerequisite`。

## 五、 长期数据治理规则

为保证项目在未来扩充至万级知识库时不发生数据质量退化，必须遵守以下规范：

### 5.1 ID 命名规范
*   **规则**：统一使用小写英文字母、数字和连字符（`-`）组合，禁止使用空格、下划线或中文。
*   **格式**：
    *   新手自学核心包：`learn-[concept-name]` (例如：`learn-g54-g59`)
    *   现场报警查阅包：`alarm-[error-prefix]` (例如：`alarm-servo-fanuc`)
    *   工具/速查卡片包：`calc-[formula]` 或 `quick-[card-type]` (例如：`calc-vc-rpm`, `quick-insert-card`)

### 5.2 分类与标签规范
*   **分类目录**：必须归属于 `知识图谱categories` 声明的 6 大主分类之一（`入门基础`, `常用代码`, `车床编程`, `铣床编程`, `加工工艺`, `故障维修`），禁止生造分类。
*   **标签约束**：每个知识点必须包含 2 到 4 个高精度 `tags`，首个 tag 必须与所属的二分类别词（如“对刀”, “顺铣”, “丝锥”）完全一致。

### 5.3 quickCheck 写法规范
*   **强制规定**：必须且仅能包含 **5 项** 以“**是否**”开头的现场操作物理确认动作。
*   **禁止项**：禁止出现任何概念定义或“检查是否正确”等无信息量的空话。
*   *正确示例*：`'程序开头是否包含了安全程序段（如G40 G80）？'`

### 5.4 关联关系与参数联动规范
*   `relatedIds`：数组内必须至少填满 3 个 ID，且引用的 ID 必须经过 `allUniqueIds` 强校验，严禁引用不存在的节点。
*   `nextId`：必须为逻辑上的下一个节点，无推荐时统一写 `"completed"`，严禁空置。
*   `params`：如果包含参数，必须有 `name` (计算器识别名)、`value` (默认值)、`unit` (标准单位) 和 `toolId` (绑定的计算器 ID，且仅限 `speed`/`feed`/`surface-speed`/`unit`/`roughness` 5个词)。

### 5.5 图谱边原因 (reason) 写法规范
*   **字数限制**：`reason` 长度必须在 **15 到 45 个汉字** 之间。
*   **内容约束**：必须写明**两者的物理工艺逻辑承接关系或在车间现场的具体避坑配合逻辑**，禁止只写“相关知识”或“同属常用代码”。

### 5.6 数据自动审计脚本未来检查项清单
未来构建流程（Build CI）中，自动审计脚本必须强制执行以下校验：
1.  **节点与 data.js 唯一性校验**：检测是否存在相同 ID 节点。
2.  **边端点死键校验**：检测 edges 中的 from/to 是否包含在 nodes 中。
3.  **无向圈检测**：检测是否存在逻辑冲突的循环 prereq 连线（如 A->B 且 B->A 且类型均为 prerequisite）。
4.  **relatedIds 与 nextId 双向闭环校验**：确保 data.js 与 knowledge_graph.json 的双向引用关系完全对称。
5.  **计算器 toolId 合法性校验**：确保 values 均属于 5 大合法计算器。

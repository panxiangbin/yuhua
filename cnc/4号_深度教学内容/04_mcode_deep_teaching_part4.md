# 04号｜M代码深度教学 Part 4（M60-M79）

> 说明：M代码大量依赖机床厂家PLC和机床选项。本文件按CNC教学与FANUC常见口径整理，自定义M码均标注风险，正式使用必须查本机说明书和M功能表。

# M60：托盘交换或程序停止 / Pallet Change or Stop

## 1. 指令名称
- **中文名称**：托盘交换或程序停止
- **英文名称**：Pallet Change or Stop
- **代码编号**：M60

## 2. 功能说明
M60（托盘交换或程序停止 / Pallet Change or Stop）的作用是：部分加工中心用于托盘交换，部分系统有其他定义。 M代码不是单纯的文字命令，它往往直接控制主轴、冷却、换刀、夹具、托盘、门锁、液压、气压或PLC辅助输出。本代码按FANUC及常见机床教学口径整理，具体动作仍受机床厂家PLC、参数和互锁条件影响。 新手学习M代码时，要先问三个问题：它控制什么设备，执行前需要满足什么条件，执行完成后有没有反馈信号。现场不能只看程序里写了M60，还要看机床面板、报警状态、气压油压、主轴状态、刀库状态和夹具状态。

## 3. 语法格式
- **标准格式**：`M60 ;`
- **常见变体**：可与S、T、G84、冷却、换刀、夹具动作或PLC等待信号配合，具体取决于本机定义。

## 4. 参数详解
- **托盘号或无参数**：部分系统不带参数，托盘逻辑由PLC处理。
- **完成信号**：交换完成后程序才能继续。
- **安全互锁**：门、工件、夹具、机器人区域必须安全。

## 5. 使用场景
1. 托盘交换、自动线、工位切换时，用于把程序动作和机床辅助机构联动起来。
2. 首件试运行时，用来检查M60执行前后机床状态是否正确。
3. 自动化加工或批量加工中，用来减少人工确认并保证流程一致。

## 6. 代码示例
**示例1：**
```gcode
%
O10600 (M60基础示例 需本机确认)
G21 G90 G54
(M60功能必须以本机说明书为准)
M60
G00 Z100.
M30
%
```

**示例2：**
```gcode
%
O10601 (M60配合安全互锁)
G21 G90 G54
G00 Z150.
M05
M60
M00 (确认M60动作完成)
M30
%
```

**示例3：**
```gcode
%
O10602 (M60加工流程中应用)
G21 G90 G54
(M60执行前确认夹具、门锁、气压油压)
M60
G00 X0 Y0 Z80.
M30
%
```

## 7. 常见错误
- **不查本机定义就照抄**：现象：程序中执行M60后机床动作和预期不同，可能出现夹具误动作、冷却异常、主轴未停或辅助设备报警。原因：M代码受厂家PLC定义影响，同号M码在不同机床上可能不同。解决：外来程序必须核对本机M代码表，未确认前不得执行。
- **忽略互锁条件**：现象：M60执行后程序停住、报警，或动作没有完成。原因：气压、液压、门锁、主轴停止、刀具夹紧、夹具到位信号不满足。解决：按报警信息和机床状态逐项检查互锁条件，再低速验证。
- **没有完成信号确认**：现象：M60动作刚输出，程序就继续往下走，夹具或外设还没到位。原因：PLC没有等待完成信号，或程序缺少确认步骤。解决：查机床逻辑，必要时使用厂家规定的等待、检测或报警确认方式。

## 8. 注意事项
1. 使用M60前必须确认本机M代码定义。
2. 涉及主轴、换刀、夹具、托盘、门和机器人时，先看互锁条件。
3. 新程序第一次运行建议单段执行，观察M代码动作是否完成。
4. 外来程序里的M代码不能按经验直接照抄。
5. 常用M代码也会受机床参数和厂家PLC影响，仍需以本机为准。

## 9. 系统差异
- **FANUC**：M代码由CNC基本功能和机床厂家PLC共同决定，M03/M04/M05/M08/M09/M30较常见，自定义码需查机床表。
- **SIEMENS**：常用M功能相近，但循环、PLC辅助功能和通道控制写法可能不同。
- **三菱**：基础M码接近FANUC口径，但自动换刀、托盘、夹具和专机输出常由厂家定义。
- **教学提醒**：知识库必须把“基础常见M码”和“厂家自定义M码”分层显示。

## 10. 实战技巧
- 老师傅看M代码，先看它控制的是主轴、冷却、刀库还是夹具，不会只背编号。
- 遇到陌生M码，先查说明书，再看机床动作，不要在工件旁边直接试。
- 调试M代码时先空机、单段、远离工件和夹具，确认动作方向和完成信号。

## 11. 相关指令
M03/M04/M05、M08/M09、M00/M01、G00/G01

## 12. 练习题
1. **选择题**：外来程序中出现M60，但你不知道本机定义，正确做法是？  
A. 直接运行  
B. 查本机M代码表并单段验证  
C. 把主轴转速调高  
D. 删除所有安全行  
**答案**：B。解析：M代码常由厂家PLC定义，不确认就运行可能触发错误辅助动作。

2. **选择题**：执行M60前最应该关注什么？  
A. 控制对象和互锁条件  
B. 程序名是否好看  
C. 机床颜色  
D. 操作员是否站得远  
**答案**：A。解析：M代码往往控制真实设备，必须确认动作对象、完成信号和安全条件。

# M70：厂家自定义辅助功能 / Builder Defined Auxiliary

- **英文名称**：Builder Defined Auxiliary
- **代码编号**：M70

## 2. 功能说明
M70（厂家自定义辅助功能 / Builder Defined Auxiliary）的作用是：无统一通用功能。 M代码不是单纯的文字命令，它往往直接控制主轴、冷却、换刀、夹具、托盘、门锁、液压、气压或PLC辅助输出。本代码属于厂家自定义高风险M码，未查本机说明书、梯形图或M功能表前禁止在正式程序中执行。 新手学习M代码时，要先问三个问题：它控制什么设备，执行前需要满足什么条件，执行完成后有没有反馈信号。现场不能只看程序里写了M70，还要看机床面板、报警状态、气压油压、主轴状态、刀库状态和夹具状态。

## 3. 语法格式
- **标准格式**：`M70 ;`
- **常见变体**：可与S、T、G84、冷却、换刀、夹具动作或PLC等待信号配合，具体取决于本机定义。

## 4. 参数详解
- **PLC定义**：参数含义由机床厂家梯形图和M功能表决定，没有统一取值范围。
- **互锁信号**：夹具、气压、液压、门锁、机器人就绪等可能参与判断。
- **等待方式**：部分M码执行后等待完成信号，部分只输出脉冲或保持信号。

## 5. 使用场景
1. 用于识别外来程序中的厂家自定义辅助动作，避免新手误运行。
2. 用于维修、改造、程序迁移时核对PLC定义和互锁条件。

- **英文名称**：Builder Defined Auxiliary
- **代码编号**：M73

## 2. 功能说明
M73（厂家自定义辅助功能 / Builder Defined Auxiliary）的作用是：可能用于自动线或机床附件控制。 M代码不是单纯的文字命令，它往往直接控制主轴、冷却、换刀、夹具、托盘、门锁、液压、气压或PLC辅助输出。本代码属于厂家自定义高风险M码，未查本机说明书、梯形图或M功能表前禁止在正式程序中执行。 新手学习M代码时，要先问三个问题：它控制什么设备，执行前需要满足什么条件，执行完成后有没有反馈信号。现场不能只看程序里写了M73，还要看机床面板、报警状态、气压油压、主轴状态、刀库状态和夹具状态。

## 3. 语法格式
- **标准格式**：`M73 ;`
- **常见变体**：可与S、T、G84、冷却、换刀、夹具动作或PLC等待信号配合，具体取决于本机定义。

## 4. 参数详解
- **PLC定义**：参数含义由机床厂家梯形图和M功能表决定，没有统一取值范围。
- **互锁信号**：夹具、气压、液压、门锁、机器人就绪等可能参与判断。
- **等待方式**：部分M码执行后等待完成信号，部分只输出脉冲或保持信号。

## 5. 使用场景
1. 用于识别外来程序中的厂家自定义辅助动作，避免新手误运行。
2. 用于维修、改造、程序迁移时核对PLC定义和互锁条件。

## 7. 常见错误
- **不查本机定义就照抄**：现象：程序中执行M73后机床动作和预期不同，可能出现夹具误动作、冷却异常、主轴未停或辅助设备报警。原因：M代码受厂家PLC定义影响，同号M码在不同机床上可能不同。解决：外来程序必须核对本机M代码表，未确认前不得执行。
- **忽略互锁条件**：现象：M73执行后程序停住、报警，或动作没有完成。原因：气压、液压、门锁、主轴停止、刀具夹紧、夹具到位信号不满足。解决：按报警信息和机床状态逐项检查互锁条件，再低速验证。
- **没有完成信号确认**：现象：M73动作刚输出，程序就继续往下走，夹具或外设还没到位。原因：PLC没有等待完成信号，或程序缺少确认步骤。解决：查机床逻辑，必要时使用厂家规定的等待、检测或报警确认方式。

- **不查本机定义就照抄**：现象：程序中执行M79后机床动作和预期不同，可能出现夹具误动作、冷却异常、主轴未停或辅助设备报警。原因：M代码受厂家PLC定义影响，同号M码在不同机床上可能不同。解决：外来程序必须核对本机M代码表，未确认前不得执行。
- **忽略互锁条件**：现象：M79执行后程序停住、报警，或动作没有完成。原因：气压、液压、门锁、主轴停止、刀具夹紧、夹具到位信号不满足。解决：按报警信息和机床状态逐项检查互锁条件，再低速验证。
- **没有完成信号确认**：现象：M79动作刚输出，程序就继续往下走，夹具或外设还没到位。原因：PLC没有等待完成信号，或程序缺少确认步骤。解决：查机床逻辑，必要时使用厂家规定的等待、检测或报警确认方式。

## 8. 注意事项
1. 使用M79前必须确认本机M代码定义。
2. 涉及主轴、换刀、夹具、托盘、门和机器人时，先看互锁条件。
3. 新程序第一次运行建议单段执行，观察M代码动作是否完成。
4. 外来程序里的M代码不能按经验直接照抄。
5. 厂家自定义M代码建议在知识库中标注红色风险标签。

## 9. 系统差异
- **FANUC**：M代码由CNC基本功能和机床厂家PLC共同决定，M03/M04/M05/M08/M09/M30较常见，自定义码需查机床表。
- **SIEMENS**：常用M功能相近，但循环、PLC辅助功能和通道控制写法可能不同。
- **三菱**：基础M码接近FANUC口径，但自动换刀、托盘、夹具和专机输出常由厂家定义。
- **教学提醒**：知识库必须把“基础常见M码”和“厂家自定义M码”分层显示。

## 10. 实战技巧
- 老师傅看M代码，先看它控制的是主轴、冷却、刀库还是夹具，不会只背编号。
- 遇到陌生M码，先查说明书，再看机床动作，不要在工件旁边直接试。
- 调试M代码时先空机、单段、远离工件和夹具，确认动作方向和完成信号。

## 12. 练习题
1. **选择题**：外来程序中出现M79，但你不知道本机定义，正确做法是？  
A. 直接运行  
B. 查本机M代码表并单段验证  
C. 把主轴转速调高  
D. 删除所有安全行  
**答案**：B。解析：M代码常由厂家PLC定义，不确认就运行可能触发错误辅助动作。

2. **选择题**：执行M79前最应该关注什么？  
A. 控制对象和互锁条件  
B. 程序名是否好看  
C. 机床颜色  
D. 操作员是否站得远  
**答案**：A。解析：M代码往往控制真实设备，必须确认动作对象、完成信号和安全条件。

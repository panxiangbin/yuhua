## 🔍 根本问题诊断

经过4轮返修，终于定位到真正的根本原因：

### 核心发现
**HTML 属性使用了 UTF-8 弯引号而非 ASCII 直引号**

- 错误字节: `e2 80 9c` / `e2 80 9d` (UTF-8 U+201C/U+201D 弯引号)
- 正确字节: `22` (ASCII 双引号)
- 影响范围: index.html 首页增强区所有 class/id/data-* 属性
- 后果: 浏览器 HTML 解析器无法正确识别属性，导致 DOM 选择器全部失效

---

### 为什么前3轮都没发现？

- **错误假设**: 认为 HTML 中存在元素就能渲染

#### 第2轮误判
- **错误假设**: 认为是 JavaScript 逻辑问题
- **忽略**: 没用 hexdump 验证 HTML 源文件编码
- **教训**: DOM 选择器失效应先检查 HTML 而非 JS

#### 第3轮误判
- **错误假设**: 认为是视图切换逻辑错误
- **忽略**: 即使修改了 active 类，仍没测试浏览器实际结果
- **教训**: 修复后必须在浏览器验证，不能仅凭代码推理

#### 第4轮突破
- 用户提供 hexdump 证据
- 对比正常文件和问题文件的字节差异
- 确认是 UTF-8 弯引号导致属性解析失败

## 🔧 终极修复

### 修复方法：批量字节替换

## 🎯 核心修复点

### 问题: HTML 属性引号编码错误
**根本原因**: 
- 文本编辑器或复制粘贴时引入了 UTF-8 智能引号
- HTML 解析器严格要求 ASCII 引号 (0x22)
- 弯引号导致属性无法被识别

**修复方案**:
- 使用 sed 进行二进制级别的字节替换
- 将 UTF-8 弯引号 (e2 80 9c/9d) 替换为 ASCII 引号 (22)

**修复效果**:
- DOM 选择器现在能正确识别所有元素
- class 和 id 属性正常工作
- data-route 等自定义属性可被读取
- JavaScript 事件绑定恢复正常

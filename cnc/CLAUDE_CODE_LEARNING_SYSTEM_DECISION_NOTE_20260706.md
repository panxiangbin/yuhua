## B. 候选 learning-cards-round2.js 评估

已全文读取（159行，12个对象，`window.CNC_LEARNING_CARDS`）。

1. **内容结构是否完整**：完整。每张卡有`id/title/level/stage/goal/minutes/imageType/body/question/answer/nextTopic`11个字段，比在线版（只有图标+标题+短描述+标签）丰富得多。
2. **教学质量是否明显优于在线版**：**明显优于**。每张卡都有具体计算题/判断题（比如card-008给了真实的Vc转速换算例题并算出确切数字4770转/分，card-010解释了R值正负号的含义，card-012给出具体报警代码5136 FSSB的排查方向），不是泛泛的概念介绍，现场实用性强于在线版当前的简短卡片文案。
3. **和当前页面结构兼容吗**：**不完全兼容，需要新建UI**。已核实`index.html`/`styles.css`/`app.js`里**没有任何**互动题/测验类组件（搜索`quiz`/`question-card`/`interaction-card`零命中）。候选卡的`question`/`answer`字段目前没有渲染载体，接入不是"换数据"那么简单，要新建一套问答交互UI。
4. **如果要接入，改动大不大**：中等偏大。至少要做：①`index.html`新增`<script src>`引入这个文件；②把`#view-study`从静态HTML改成JS动态渲染12张卡；③新建问答交互组件；④给每张候选卡补上`entryId`字段（当前候选卡本身没有这个字段，3号建议的11个映射是"外挂"上去的，不是候选文件自带的）；⑤`bindStudyCards()`要从"标题模糊匹配"改写成"按`entryId`精确查找"。这不是"接一个文件"，是一次前端小型重构。
5. **如果不接入，原因是什么**：候选卡内容质量确实更好，但当前12关的问题根源不是"内容不够好"，是"点击链路断了"——把候选卡换上去，如果不同时补好问答UI和entryId映射，一样会遇到点击断链问题，只是断链原因从"标题匹配不上"变成"候选卡本身就没做entryId字段"。换皮不解决问题，反而多引入一次UI重构风险。
6. **最终结论**：**值得部分吸收，不建议整体接入**。候选卡的**文案内容**（body/question/answer的写法水准）值得吸收进现有12关的内容深化里；但候选卡的**整个数据结构和UI形态**不建议现在整体切换，成本和当前"先把9个断链关卡接上"这个更紧急的任务不成比例。

## D. 给Codex的最终建议

1. **现在应该优先修当前在线版，不切到候选版。** 理由：在线版只差"把`STUDY_CARD_MATCH_RULES`的12条规则改成精确的`id`映射"这一步代码改动（改`app.js`一个数组，不涉及UI），10/12立刻就能接上；候选版需要新建问答UI+新数据结构，投入产出比明显更差。
2. **可以立刻派工的内容**：把C部分"最终版映射清单"里的10条，直接改写`STUDY_CARD_MATCH_RULES`里对应条目的`id`字段（参考已有的"告诉机床活儿在哪"那条写法，加`id: 'xxx'`即可精确匹配，不用再依赖关键词模糊搜索）。这是一处小范围、低风险的代码改动，适合直接派给1号（OpenCode）。
3. **先不要动的内容**：①第10关"致命的小数点"——需要先决定新写一条什么内容的知识条目，这是内容决策，不是代码任务；②候选版`learning-cards-round2.js`的问答UI/整体接入——工作量不小，且当前更紧急的"9个断链关卡"修完之后再评估要不要吸收候选版的文案质量，现在动它会分散精力。

## 一、知识条目相似性与重复审计

在合并了 [data.js](file:///F:/AI工作台/cnc_param_quickfinder/data.js)、[kb-extra.js](file:///F:/AI工作台/cnc_param_quickfinder/kb-extra.js) 以及 3 个 `knowledge-core-*.js` 后，对 415+ 原始条目进行清点，发现了以下条目重叠和相似问题：

1.  **重复且冲突的条目**:
    *   `m03-m04-m05` (在 `data.js` 中定义为“M03 / M04 / M05 主轴控制”) 与 `learn-m03-m05` (在 `knowledge-core-03.js` 中定义为“M03 / M04 / M05 主轴控制”) 重复。
    *   *诊断*：两者的 `id` 不同，但 `title` 和 `code` 几乎完全一致。前端在合并数据源时会同时加载这两个节点，导致用户在列表里看到两个相同的“主轴控制”，且点击时会导向两个不同的详情页面。
2.  **报警解析重复**:
    *   `fanuc-alarm-common` (在 `data.js` 中) 与 `learn-fanuc-alarm-common` (在 `knowledge-core-03.js` 中) 重复。
    *   *诊断*：这是两个不同阶段由不同模型生成的报警代码条目，数据字段有些不完整。
3.  **标题相似内容相近条目**:
    *   `fault-home-fail` ("回不了零点时先查什么") 与 `fault-home-reference` ("回零失败与参考点异常")。
    *   *诊断*：两者都归属于报警排查，但前者主要是发那科系统 JOG 摇不回原点的排查步骤，后者偏向磁栅尺硬件限位问题，标题相似，建议重命名合并。

## 二、占位草稿节点与噪音清理

清查发现，`knowledge-core-*.js` 存在大量 **草稿节点（占位符）**，特征是包含大量的问号 `?????` 或测试路径：

1.  **无效总览目录节点**:
    *   例如 `kb-root-01_编程基础`、`kb-root-02_机床操作`、`kb-root-03_CAM软件` 等。
    *   *缺陷*：这些条目的 `example` 和 `nextLearn` 字段直接填充为 `"???????????????????????"`，它们只是本地文件夹的 README 文件转成的 JS，不能给操机人员提供任何实际帮助。
2.  **未清洗的绝对物理路径暴露**:
    *   许多 Core 条目的 `source` 直接包含 `F:/AI工作台/04_数控知识库/...`。这导致用户在前台搜索含有磁盘盘符“F”或路径字符“04”等词汇时，直接触发了全局的 `normalizeText` 匹配，从而吐出大片不相关的占位节点。

## 三、推荐的核心池与检索池划分 (基于 Priority Pool JSON)

为了让网站前台反应迅速、不卡死，建议对 415+ 条目按照优先级划分为以下三个功能池（见 [knowledge_entry_priority_pool.json](file:///F:/AI工作台/cnc_param_quickfinder/gemini_output/knowledge_entry_priority_pool.json)）：

### 1. 核心入门池 (CORE_ENTRY) - P0 级 (建议首屏必载)
*   *入选条件*：12关学习系统绑定的知识点，以及车间绝对高频的指令（G54, G43, G01, G02, 对刀）。
*   *条目数*：约 15 条。
*   *目的*：支撑新手路线的前台极速渲染，不依赖任何网络延时。

### 2. 搜索高频联想池 (HIGH_FREQUENCY_SEARCH) - P1 级 (按需合并载入)
*   *入选条件*：常用的 G/M 代码（G00-G99, M00-M99）、常规报警（5136, 伺服报警）、5个参数计算器。
*   *条目数*：约 80 条。
*   *目的*：在前台搜索框输入时，优先匹配这一池，提高现场检索命中率。

### 3. 备用挂载池 (DRAFT_STANDBY) - P2 级 (从内存剥离)
*   *入选条件*：总览类 README、未清洗的草稿、超长 CAM 软件配置。
*   *条目数*：300+ 条。
*   *建议*：不要将其扁平化塞入 app.js 中，前台只保留其 ID 和 Title 索引。只有在全局搜索无法在 P0/P1 中命中时，或者用户点击“加载完整本地库”时，才加载。

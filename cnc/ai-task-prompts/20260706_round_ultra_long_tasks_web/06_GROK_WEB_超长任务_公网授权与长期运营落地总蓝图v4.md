## 一、你这次不能只写架构，要写“落地全链路”

这次不是只回答：

1. 公网发布路线
2. 授权访问路线
3. 手机端访问体验
4. 图片海量资源的公网策略
5. 长期更新流程

7. 风险与回滚
8. 管理员操作流程
9. 用户进入流程
10. 未来收费/会员扩展的兼容性

## 二、你这次必须覆盖的 12 个大章节

你最终文档必须完整展开以下 12 章，不能缺：

### 第1章：项目现状复盘

要写清：

- 当前是静态站还是半静态
- 当前已经有哪些能力
- 当前最大短板是什么
- 当前最紧急的问题是什么

### 第2章：公网发布路线总对比

至少对比：

- GitHub Pages
- Cloudflare Pages
- Vercel
- 静态站 + Cloudflare Access
- 轻后端模式

每条路线都要写：

1. 安全性
2. 成本
3. 稳定性
4. 维护复杂度
5. 适不适合这个项目

### 第3章：当前最推荐路线

必须给出明确推荐，不准模糊。

要写清：

- 你推荐什么
- 为什么推荐
- 为什么不推荐另外几条

### 第4章：授权访问设计

必须展开：

1. 公开区和授权区怎么分
2. 手机端授权入口怎么做
3. 邀请码、私密链接、邮箱授权分别适合什么场景
4. 如何防止“全部挡死导致传播变差”

### 第5章：用户进入流程设计

必须分别写：

1. 新访客第一次进入
2. 已授权用户再次进入
3. 分享链接进入但未授权
4. 已过期授权用户
5. 管理员手工放行用户

### 第6章：管理员运营流程

必须写完整管理员视角：

1. 生成链接
2. 发邀请码
3. 失效旧链接
4. 替换新链接
5. 区分普通用户和高级用户
6. 管理资料开放范围

### 第7章：图片与大资源的公网策略

这个项目后面会有非常多图片，所以你必须专门写：

1. 图片放在什么目录结构更稳
2. 图片怎么做批量命名
3. 公网加载如何防止太慢
4. 首屏加载多少，剩下怎么懒加载
5. 如何避免“1000张图把首页拖死”

### 第8章：长期更新流程

这一章必须非常具体：

1. 网站日常如何更新
2. 文字怎么更新
3. 图片怎么更新
4. 新知识点怎么上线
5. 更新时如何避免把线上搞坏

### 第9章：风险清单

至少列出 **20 条风险**，不能少。

例如：

- 链接泄露
- 图片过多导致加载慢
- 静态缓存不同步
- 授权策略误伤
- 管理员操作过于复杂
- 手机端弹层过重

每条风险必须配：

1. 风险描述
2. 严重等级
3. 怎么预防
4. 出现后怎么补救

### 第10章：回滚与兜底方案

必须写：

1. 上线失败怎么回退
2. 授权策略失误怎么回退
3. 图片资源失误怎么回退
4. 页面打不开时怎么快速降级

### 第11章：分阶段路线图

必须拆成：

1. 现在就能做
2. 下一阶段做
3. 长期阶段做

每个阶段都要写清：

- 目标
- 工作项
- 风险
- 成果

### 第12章：给Codex的可执行清单

这章必须是面向总指挥的。

要写成：

1. 哪些适合本地AI做
2. 哪些适合网页版AI继续研究
3. 哪些必须人工确认
4. 下一轮最优先的 10 件事

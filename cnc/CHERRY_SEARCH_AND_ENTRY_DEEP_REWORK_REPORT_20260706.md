## 🔧 二、修掉的结构性问题

### 问题1：搜索函数调用链不清晰 ✅ 已修正

**原问题**:
- `expandSearchTerm()` 和 `matchesKeyword()` 缺少注释文档
- 无法追踪别名扩展是否生效
- 命中来源不可解释

**修正方案**:
1. 为两个函数添加完整的JSDoc注释
2. 集成 `CNC_SEARCH_DEBUG` 日志系统
3. 在扩展和匹配时记录详细日志
4. 提供 `explainMatch()` 方法解释命中来源

**修正后的调用链**:
```
用户输入 → expandSearchTerm() [记录扩展日志]
  ↓
扩展词数组 → matchesKeyword() [逐条匹配]
  ↓
命中成功 → logMatch() [记录匹配日志]
  ↓
返回结果
```

### 问题2：学习入口映射规则分散 ✅ 已修正

**原问题**:
- `STUDY_CARD_MATCH_RULES` 硬编码在 app.js 内部
- 规则难以维护和扩展
- 缺少映射验证机制

**修正方案**:
1. 将规则提取到独立模块 `study-entry-rules.js`
2. 提供统一的查找接口
3. 增加映射验证功能
4. app.js 优先使用外部模块，保留内部降级逻辑

**修正后的结构**:
```
study-entry-rules.js (规则定义 + 查找逻辑)
  ↓
app.js (优先使用外部模块)
  ↓
bindStudyCards() (统一绑定)
```

### 问题3：首页搜索入口状态不同步 ✅ 已修正

**原问题**:
- 首页快速搜索框跳转到工作区后，工作区搜索框为空
- `data-jump-keyword` 按钮没有同步搜索框状态
- 缺少跳转日志，无法诊断问题

**修正方案**:
1. 在 `bindEnhancedUI()` 中增强快速搜索逻辑
2. 跳转时显式调用 `navigate('workspace', { keyword })`
3. 同步更新 `dom.searchInput.value`
4. 添加 `console.log` 跟踪跳转行为

**修正后的流程**:
```
首页搜索框输入 "G02"
  ↓
[快速搜索] 触发搜索: G02
  ↓
state.keyword = "G02"
dom.searchInput.value = "G02"
  ↓
navigate('workspace', { keyword: "G02" })
  ↓
工作区显示搜索结果，搜索框显示 "G02"
```

### 问题4：快捷跳转按钮缺少状态重置 ✅ 已修正

**原问题**:
- 点击 `data-jump-keyword` 按钮后，如果之前有设置分类过滤器，搜索结果不全
- 缺少 `state.selectedCategory` 重置

**修正方案**:
1. 在 `bindRouteButtons()` 中增强 `data-jump-keyword` 处理
2. 显式重置 `state.activeFilter = "all"`
3. 显式重置 `state.selectedCategory = "全部栏目"`
4. 同步工作区搜索框
5. 添加控制台日志

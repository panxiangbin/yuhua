## alarm-faq-001 — PS0001

**标题**: THP报警 — 程序开头没人性（没写安全代码）

**白话解释**: 程序开头缺少必要的安全指令，比如没加G00/G01这种基础指令就直接跑，系统看不懂你想干啥。

**危险等级**: 低

**系统范围**: FANUC为主

**可能原因**:

1. 程序开头缺少G代码或M代码引导
2. 用了一个不是标准G代码的字符开头
3. 程序头格式不对，系统不认识第一个字
4. 前一个程序没彻底复位就直接加载新程序

**先查什么**:

1. 打开程序看第一行是什么内容
2. 确认第一行是不是合法的G代码或M代码
3. 检查程序开头有没有多余的空格或乱码字符
4. 试着手动在开头加G00 G90看看

**关键词**: 程序开头错误、THP、程序格式

## alarm-faq-002 — PS0010

**标题**: 非法G代码 — 系统不认识你写的G代码

**白话解释**: 你在程序里写了一个G指令，但系统的内存里没这玩意，不认识。

**危险等级**: 低

**系统范围**: FANUC为主

**可能原因**:

1. 拼错了G代码（比如G001写成了G01多一个0）
2. 这台机床不支持这个G代码功能
3. 用了宏程序但调用的G代码没注册
4. 小数点位置不对导致系统解析错误

**先查什么**:

1. 找到报警时程序停在哪一行
2. 把那行的G代码跟说明书手册对一下
3. 看看是不是选错了加工模式（比如车铣不同）
4. 查一下系统参数里这个G代码有没有开通

**关键词**: 非法G代码、G指令错误、程序格式

## alarm-faq-003 — PS0020

**标题**: 超过最大指令数 — 一行里写了太多东西

**白话解释**: 同一行G代码里塞了太多指令，系统记不过来了。

**危险等级**: 低

**系统范围**: FANUC为主

**可能原因**:

1. 一行里同时写了好几个G代码/M代码
2. 宏程序调用时参数太多挤在一行
3. 系统参数里单行最大指令数设得太小
4. 后处理输出格式不规范，把多行合并了

**先查什么**:

1. 找到报警那行，看看写了几个指令
2. 把长行拆成多行试试
3. 查机床参数里单行最大指令数的设定值
4. 检查后处理配置，别让它把多行合并成一行

**关键词**: 指令数超限、单行过长、程序格式

## alarm-faq-004 — PS0030

**标题**: 坐标轴指令重复 — 同一行里两次指定同一个轴

**白话解释**: 在同一行程序里，你把X轴（或Y/Z）写了两次，系统不知道该听哪个。

**危险等级**: 低

**系统范围**: FANUC为主

**可能原因**:

1. 后处理有问题，同一个轴生成了两个指令
2. 手动改程序时忘了删旧的坐标值
3. 宏程序计算后重复输出了同一个轴
4. 复制粘贴代码时没清理干净

**先查什么**:

1. 看报警行的坐标值，找哪个轴出现了两次
2. 删掉多余的坐标指令
3. 检查后处理是不是有重复输出bug
4. 如果是宏程序，检查变量赋值逻辑

**关键词**: 坐标轴重复、程序错误、指令冲突

## alarm-faq-005 — PS0040

**标题**: G代码/Q地址错误 — 指令和地址码不匹配

**白话解释**: G代码后面跟的地址码不对，比如钻循环里Q值给了不该给的G代码。

**危险等级**: 低

**系统范围**: FANUC为主

**可能原因**:

1. 固定循环（G81/G83等）里Q值用法不对
2. 地址码字母用错了（应该用R的你用了Q）
3. 系统参数限制了某些地址码的使用范围
4. 宏程序调用的参数地址不匹配

**先查什么**:

1. 找到报警那行，核对G代码和后面的地址字母
2. 翻编程手册看这个G代码允许哪些地址码
3. 检查是不是用了不兼容的固定循环格式
4. 如果是宏程序，看看#代码和地址的对应关系

**关键词**: G代码地址错误、Q地址、编程错误

3. 检查后处理配置
4. 检查宏程序的输出逻辑

**关键词**: 地址码重复、程序错误、语法错误

## alarm-faq-007 — PS0060

**标题**: P/S指令值超出范围 — 数写太大了

**白话解释**: 给G代码或M代码后面跟的数太大了，超过了系统允许的范围。

**危险等级**: 低

**系统范围**: FANUC为主

**可能原因**:

1. F（进给）值写成了天文数字
2. S（主轴转速）超出了机床最高转速
3. 坐标值超出了机床行程范围
4. 延时时间（P）写成了不合理的大数

**先查什么**:

1. 看报警停在程序哪一行，哪个数值异常大
2. 输错的那一行手动纠正数值
3. 查机床各轴行程和主轴最高转速的软限位
4. 检查是不是小数点位置错了

**关键词**: 数值超范围、P/S报警、数据格式

## alarm-faq-008 — PS0070

**标题**: M代码不在标准范围 — 系统不认识的M指令

**白话解释**: 你写了一个M代码，但这个机床的系统里没有实现这个M指令的功能。

**危险等级**: 低

**系统范围**: FANUC为主

**可能原因**:

1. M代码号写错了（比如M30写成M03）
2. 这台机床没开通这个M代码功能
3. 用了用户宏的M代码但没注册
4. M代码范围被系统参数限制住了

**先查什么**:

1. 找到报警行的M代码数字
2. 查机床的M代码表确认这个号有没有定义
3. 对比标准M代码范围和机床自定义M代码
4. 检查系统参数里M代码范围限制

**关键词**: M代码错误、非法M代码、编程错误

## alarm-faq-009 — PS0080

**标题**: G代码格式冲突 — 同组的G代码用混了

**白话解释**: 你把两个不能共存的G代码写在了同一行或程序里，比如G01和G00在同一模态组里打架了。

**危险等级**: 低

**系统范围**: FANUC为主

**可能原因**:

1. 同一行里写了互斥的G代码（如G01和G02）
2. 程序里切换了加工模式但没取消前一个G代码
3. 固定循环中的G代码和模态G代码冲突
4. 后处理在同一行输出了两个同组G代码

**先查什么**:

1. 看报警行同时写了哪几个G代码
2. 查编程手册确认这些G代码是不是同一组
3. 把冲突的G代码拆分到不同行
4. 检查后处理输出逻辑

**关键词**: G代码冲突、模态组冲突、格式错误

## alarm-faq-010 — PS0090

**标题**: 程序中用了非法字符 — 写了系统不认识的符号

**白话解释**: 程序里冒出来一个系统看不懂的字符，可能是乱码、中文符号或键盘误触打的。

**危险等级**: 低

**系统范围**: FANUC为主

**可能原因**:

1. 不小心打了中文标点符号
2. 从外部复制文字时带了不可见字符
3. 键盘误触输入了特殊符号
4. USB拷程序时编码格式不对产生乱码

**先查什么**:

1. 找到报警那行，仔细看有没有奇怪的符号
2. 把可疑行重新手动输入一遍
3. 检查程序文件编码格式（用纯文本ASCII最安全）
4. 删掉这行重新写

**关键词**: 非法字符、程序乱码、编码错误

## alarm-faq-011 — PS0100

**标题**: 宏程序变量未定义 — 用了没赋值的变量

**白话解释**: 程序里用了#开头的变量，但这个变量之前没给过值，系统不知道它是多少。

**危险等级**: 低

**系统范围**: FANUC为主

**可能原因**:

1. 用了#变量但前面没有赋值语句
2. 变量号写错了（应该用#101你写了#201）
3. 宏程序调用时没传参数

**先查什么**:

1. 找到报警行看用了哪个#变量
2. 往前翻程序看这个变量有没有赋过值
3. 确认是局部变量（#1-#33）还是全局变量（#100+）
4. 检查宏程序调用时参数传递对不对

**关键词**: 宏变量、变量未定义、宏程序

## alarm-faq-013 — PS0120

**标题**: 圆弧指令参数错误 — 圆弧数据给得不对

**白话解释**: 你写G02/G03走圆弧时，半径或终点位置算得不对，系统画不出这个弧。

**危险等级**: 低

**系统范围**: FANUC为主

**可能原因**:

1. R值（半径）写得太小，够不到终点
2. I/J/K值计算有误
3. 起点到终点的距离大于直径（R半径方式）
4. 圆弧所在的平面没指定（忘了G17/G18/G19）

**先查什么**:

1. 检查报警行的R值或I/J/K值
2. 用勾股定理算一下起点到终点的距离
3. 确认圆弧半径 > 起点到终点距离的一半
4. 确认指定了正确的平面（G17/G18/G19）

**关键词**: 圆弧错误、G02/G03、R值错误

## alarm-faq-014 — PS0130

**标题**: 子程序嵌套过深 — 子程序套子程序套太多了

**系统范围**: FANUC为主

2. 查系统参数看最大嵌套层数是多少
3. 检查子程序里有没有不该出现的M98/M99
4. 看有没有形成循环调用（A调B、B调A）

**关键词**: 子程序嵌套、M98/M99、层数超限

## alarm-faq-016 — SV0401

**标题**: 伺服准备信号断开 — 伺服放大器没准备好

**白话解释**: CNC给伺服放大器发了准备好信号，但放大器没回音，相当于叫了没人应。

**危险等级**: 高

**系统范围**: FANUC

**可能原因**:

1. 伺服放大器电源没通或保险烧了
2. 急停回路被按下了，伺服没使能
3. 串行编码器线断了或接触不好
4. 伺服放大器本身坏掉了
5. 24V控制电源有问题

**先查什么**:

1. 看伺服放大器上的LED指示灯亮不亮
2. 确认急停按钮有没有被按下去
3. 检查伺服放大器的控制电源（24V）
4. 看放大器有没有冒烟或异味
5. 断电重启一次看能不能恢复

**关键词**: 伺服准备、放大器断开、SV0401

## alarm-faq-017 — SV0402

**标题**: 伺服过载 — 电机太累了转不动

**白话解释**: 伺服电机被卡住了或者受力太大，电流一直超标，系统怕烧电机所以报警了。

**危险等级**: 高

**系统范围**: FANUC

**可能原因**:

1. 机械卡死（导轨缺油、丝杠卡住、轴承坏了）
2. 切削负载太大，吃刀太多了
3. 电机抱闸没松开
4. 伺服参数设置不对（比如电流限值设太小）

**先查什么**:

1. 手动转一下对应轴，看是不是卡住了
2. 检查导轨润滑是不是正常
3. 听电机有没有异响
4. 摸电机外壳烫不烫（小心烫伤）
5. 减小进给量和吃刀量试试

**关键词**: 伺服过载、电机过热、过载报警

## alarm-faq-018 — SV0410

**标题**: 伺服停止误差超差 — 停下来了但没停准位置

**白话解释**: 系统让电机停到某个位置，但电机停的地方跟指令差了太多，超了允许范围。

**危险等级**: 中

**系统范围**: FANUC

**可能原因**:

1. 伺服增益参数设太低，定位锁不住
2. 机械传动间隙太大（丝杠反向间隙）
3. 电机刹车没完全刹住
4. 负载突变导致位置偏移
5. 编码器反馈信号有干扰

**先查什么**:

1. 看看这个轴实际位置和指令位置差了多少
2. 手动推推这个轴有没有明显的间隙
3. 检查伺服增益参数（如1825）
4. 检查反向间隙补偿参数
5. 看看是不是最近换过机械部件

**关键词**: 停止误差、定位不准、伺服超差

## alarm-faq-019 — SV0411

**标题**: 伺服移动误差超差 — 跑的过程中跟丢了

**白话解释**: 电机在跑的过程中，实际位置跟指令位置越差越大，系统追不上了。

**危险等级**: 高

**系统范围**: FANUC

1. 切削负载太大把电机拖慢了
2. 加速度（加加速时间）设得太快
3. 电机扭矩不够
4. 丝杠或导轨有卡滞
5. 位置环增益设得不合适

**先查什么**:

1. 减小进给速度看看还报不报
2. 降低加速度设定（参数1620）
3. 检查切削量是不是太大了
4. 手动盘车感觉是否有卡点
5. 检查伺服电机输出扭矩监视值

**关键词**: 移动误差、跟丢、伺服超差

## alarm-faq-020 — SV0412

**标题**: 伺服电流异常 — 电流突然爆表

**白话解释**: 伺服放大器检测到流向电机的电流突然变得很大，超出正常范围。

**危险等级**: 紧急

**系统范围**: FANUC

**可能原因**:

1. 电机线圈短路（烧了或受潮）
2. 动力线破皮搭铁了
3. 伺服放大器内部IGBT坏了
4. 电机刹车短路
5. 电机编码器线断裂导致电流失控

**先查什么**:

1. 关机断电，拔掉电机动力线，用万用表量电机三相电阻
2. 检查动力线有没有破损、烧焦
3. 把电机和机械脱开，空转测试
4. 看放大器上有没有烧焦的味道
5. 互换放大器测试

**关键词**: 电流异常、伺服短路、电机烧毁

## alarm-faq-021 — SV0413

**标题**: 伺服过电压 — 电压太高了

**白话解释**: 伺服放大器内部的直流母线电压超过了安全值，再不报警就要炸电容了。

**危险等级**: 高

**系统范围**: FANUC

**可能原因**:

1. 再生放电电阻坏了，能量放不出去
2. 电机减速时回馈能量太大（急停减速太快）
3. 输入电源电压偏高
4. 再生放电回路接线松了
5. 多个轴同时急停减速

**先查什么**:

1. 量一下输入电源电压是不是正常
2. 检查再生放电电阻有没有烧断
3. 检查再生放电回路接线
4. 降低减速时间常数试试
5. 听听再生电阻有没有异常响声

**关键词**: 过电压、母线电压、再生放电

## alarm-faq-022 — SV0414

**标题**: 伺服欠电压 — 电压不够了

**白话解释**: 伺服放大器里的直流电压掉得太低了，电机没力气干活了。

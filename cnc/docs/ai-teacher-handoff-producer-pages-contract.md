# AI CNC 老师一次性交接生产端 Pages 公网验收契约

## 目标

AI CNC 老师已经能够在高风险阻断或安全原理回答后，把本次问题以同标签页临时数据交给判断说明页。仓库代码通过浏览器测试，不等于这套生产端已经进入正式 `main` 和 GitHub Pages。本契约要求对 `cnc/ai-teacher.html` 做当前分支、远程 `main` 与 Pages 公网的精确部署核验。

## 精确资源核验

门禁使用随机查询参数、`cache: no-store`、禁止缓存请求头读取：

- 当前检出的 `cnc/ai-teacher.html`；
- 远程 `main` 的同一文件；
- Pages 公网的同一文件。

远程 `main` 与 Pages 必须同时满足：

- HTTP 200；
- 字节长度完全一致；
- SHA-256 完全一致；
- 一次性交接生产端语义契约完整。

最多进行 18 次真实部署等待，每次间隔 10 秒。不得将重试次数设为 0，也不得只凭网页可打开就宣称部署完成。

## 一次性交接生产端边界

页面必须继续保持：

- 固定键 `cnc_ai_teacher_explainability_handoff_v1`；
- Schema 版本 1；
- 最长有效期 5 分钟；
- 问题长度 1～120 个字符；
- 来源固定为 `ai-teacher`；
- 仅 `blocked` 与 `safety-boundary` 两类回答允许写入；
- 仅写入当前标签页 `SessionStorage`；
- 写入前清理遗留交接；
- 普通学习问题和快捷问题不生成交接，并清理旧数据；
- 入口使用固定相对地址 `./ai-teacher-explainability.html`；
- 问题不得进入 URL 查询参数或片段；
- 不得写入 LocalStorage、IndexedDB、成长档案、错题或长期学习记录；
- 不调用外部模型，不使用 `fetch`、`XMLHttpRequest`、`WebSocket` 或 `EventSource` 上传问题。

消费端仍负责读取后立即删除、校验来源/意图/长度/时效并重新调用正式分类器。生产端与消费端不能分别维护两套风险判定规则。

## 两阶段部署边界

拉取请求阶段允许当前分支页面暂时不同于 `main`，但必须同时确认：

1. 当前分支自身满足全部生产端契约；
2. 当前 `main` 与 Pages 公网逐字节一致；
3. 诊断明确记录 `branchDeploymentPending: true`，不得把分支功能宣称为已经上线。

合并到 `main` 后，由 `push` 或手动复验触发的同一门禁必须要求：

- 当前检出页面与远程 `main` 完全一致；
- 远程 `main` 与 Pages 公网完全一致；
- `branchDeploymentPending: false`。

只有以上条件全部成立，才允许报告一次性交接生产端已经正式部署。

## 安全与技术内容边界

判断说明只解释风险类别和判断理由，不提供固定转速、进给、安全高度、参数写入、刀补值、联锁绕过、盲目复位或现场放行方法。不确定的机床参数、报警、刀补和安全步骤必须核对相同版本原厂手册、企业制度、受控工艺与现场条件，并由授权人员确认。

## 失败处理

成功和失败都必须上传结构化 `report.json` 与 `findings.txt`。失败时必须读取真实 HTTP 状态、字节数、SHA-256、缓存响应头和语义缺失项；不得删除测试、降低断言、跳过步骤，或把 cancelled/skipped 当作成功。

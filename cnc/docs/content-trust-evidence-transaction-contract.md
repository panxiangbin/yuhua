# CNC 内容复核证据事务一致性契约

## 目标

资料清单和逐条复核记录以后可能由人工或自动工具批量导入。单独校验最终 JSON 只能证明“最后文件结构合法”，不能识别以下风险：

- 基于旧版本台账继续写入，覆盖别人已经提交的记录；
- 只写入一半文件，事务记录与目标台账摘要不一致；
- 删除或原地改写已经登记的来源和逐条复核历史；
- 新增逐条复核记录，却没有登记同一发布机构、资料版本和适用系统的资料清单；
- 状态、计数、记录数组和事务汇总彼此漂移；
- 台账没有任何实质变化，却刷一条无意义事务记录。

本契约只保护 CNC 高风险内容的证据台账更新过程，不改变任何报警、G/M 代码、参数、刀补或安全结论。

## 事务文件

当 `cnc/content-trust-evidence-ledger.json` 相对 PR 基线或 `main` 上一个提交发生变化时，必须同时提交：

```text
cnc/content-trust-evidence-transaction.json
```

事务记录必须包含：

```text
schemaVersion
transactionId
expectedBaseLedgerSha256
nextLedgerSha256
committedAt
actor
changeReason
operationSummary
```

其中两项 SHA-256 按文件原始 UTF-8 字节计算：

- `expectedBaseLedgerSha256`：更新前台账；
- `nextLedgerSha256`：更新后台账。

因此，基于过期台账、漏写目标文件或事务记录未同步都会直接失败。

## 原子更新边界

正式校验器先分别调用现有证据台账校验器检查更新前和更新后文件，再检查差异：

1. 高风险数据集名称、数量、优先级、资料请求和全局治理字段不得被资料导入事务改写。
2. 已登记的 `sourceRecords` 和 `itemReviewRecords` 采用追加不可变策略：不得删除，不得原地覆盖。
3. 需要修正历史时，应追加新的可追溯资料或复核记录，不得擦除旧证据。
4. 新增逐条复核记录必须能在目标台账中找到同一发布机构、文档名称、版本和适用系统或机床的资料清单记录。
5. `reviewedItemCount`、状态流转和 `readyForItemReview` 继续由正式台账校验器约束。
6. `operationSummary` 必须与真实差异完全一致，包括变更数据集数、资料清单新增数、逐条记录新增数、唯一条目新增数和状态流转数。
7. 台账未变化时，不允许单独改写事务记录；台账变化时，不允许缺少事务记录。

## 工作流基线选择

- Pull Request：以 `github.event.pull_request.base.sha` 中的台账为更新前基线。
- 推送到 `main`：以上一个提交 `HEAD^` 中的台账为基线。
- 工作流使用完整 Git 历史读取基线文件，不使用测试夹具伪造主分支状态。

## 自动化测试

`cnc/tests/content-trust-evidence-transaction-smoke.cjs` 至少覆盖：

- 合法的资料清单原子导入；
- 合法的资料清单与逐条记录同事务导入；
- 过期基线摘要；
- 错误目标摘要；
- 事务汇总数量漂移；
- 无意义事务；
- 治理字段被改写；
- 逐条记录缺少匹配资料清单；
- 状态或计数半写入；
- 删除既有资料；
- 原地改写既有逐条记录；
- 未受控事务字段。

成功只表示更新过程具备一致性和可追溯边界，不表示任何 CNC 技术条目已经完成原厂资料复核。

# G50 多语义运行时可信度审计

> 审计基线：`main@633e16dea1587e03341fb7abceb2de28e3eaf19e`
>
> 目标读者：零基础 CNC 学习者与内容维护者。
>
> 本文只定义安全边界与后续验收条件，不提供可直接复制到真实机床的固定转速、坐标、倍率或其它工艺参数。

## 1. 为什么继续审计 G50

当前 `cnc/gm-code-complete.js` 已把 G50 标为高风险，并明确提示不同机型/控制器可能存在不同语义，要求核对当前 CNC 与机床厂原厂手册。这一层方向正确。

但 `cnc/search-aliases.js` 的第二层高风险内容归一化器目前覆盖 G10、G28、G53、G92、G93、G94、G95、G96、G97、G98、G99，没有 `normalizeG50`。这意味着：如果以后批量生成基础表、内容迁移或合并冲突使 G50 基础条目退化，运行时第二层防御不能像 G93/G94/G95 等条目一样把安全边界重新补齐。

G50 恰好属于“同一代码在不同机型上存在明显语义差异”的典型内容，因此只依赖基础表并不够稳健。

## 2. 原厂资料交叉验证

本次只把已核对的原厂资料当作“明确实例”，不把某一品牌规则扩展成所有 CNC 的通用结论。

### Haas 车床实例

Haas 当前车床资料把 G50 定义为 **Spindle Speed Limit（主轴转速限制）**，列在 Group 00；官方 G50 页面说明它可限制控制器允许的最高主轴转速，并用于恒表面速度 G96 场景。

来源：

- Haas Automation — `G50 Spindle Speed Limit`
- Haas Automation — `Lathe - G-Codes`

### Haas 铣床实例

Haas 当前铣床 G 代码表把 G50 定义为 **Cancel Scaling（取消缩放）**，列在 Group 11，与 G51 Scaling 配对。

来源：

- Haas Automation — `Mill - G-Codes`
- Haas Automation — `Mill Operator's Manual / Rotation and Scaling`

### 审计结论

仅同一厂商的当前车床与铣床资料，就已经足以证明：

**不能把“G50 = 主轴限速”或“G50 = 取消缩放”教成跨机型固定口诀。**

平台必须先确认机床类型、当前 CNC、G50 所属组别、地址含义和机床厂原厂手册，再解释本机语义。

对于其它品牌、旧控制器或旧程序中可能出现的坐标设定等语义，本平台不得仅凭常见经验下定论；只有拿到对应当前 CNC/机床厂原厂手册后，才能把具体格式写成可执行知识。

## 3. 当前内容的优点与剩余缺口

当前基础条目已经做到：

- 风险等级为“高”；
- 标题同时提示坐标设定、主轴限速、缩放取消等多语义；
- 明确要求先确认当前 CNC；
- 明确拒绝把 `G50 Sxxxx` 当成跨系统通用格式；
- 涉及主轴最高转速时，提醒同时核对主轴、卡盘、装夹、工件、刀具和机床配置限制；
- 示例没有提供可直接照抄的固定 S 数值。

剩余高价值缺口是：

1. 运行时第二层没有 `normalizeG50`；
2. 没有独立的 G50 多语义可信度门禁，无法阻止未来基础表回退；
3. 当前高风险归一化链已经到 `boundary-9`，但 G50 尚未纳入该链的永久约束；
4. `search-aliases.js` 属于 PWA 离线核心资源，若增加 G50 运行时保护，必须正规推进构建/缓存版本，不能只改脚本却继续复用旧缓存标记；
5. 后续必须同时验证联网、Service Worker、冷离线与版本升级场景，避免“在线正确、离线仍是旧 G50 内容”。

## 4. 后续运行时整改硬门槛

后续实现 `normalizeG50` 时，至少必须保持以下边界：

- `risk` 固定为“高”；
- 明确说明 G50 **不是跨机型同一语义**；
- 先确认机床类型、当前 CNC、G50 组别/模式和机床厂原厂手册；
- 对已验证的车床语义，只能表述为“部分明确支持该语义的车床 CNC 中用于主轴最高转速限制”；
- 对已验证的铣床语义，只能表述为“部分明确支持该语义的铣床 CNC 中用于取消缩放”；
- 不得把某品牌的 Group 00 / Group 11 直接推广到其它控制器；
- 不得提供可直接照抄的固定 `S`、坐标、倍率或其它加工参数；
- 涉及恒线速度时，必须同时提示主轴、卡盘、装夹、工件、刀具及机床配置的允许转速/安全限制；
- 涉及缩放取消时，必须提示先确认本机是否存在相应缩放功能、当前缩放状态及配对取消规则；
- 旧程序出现其它 G50 语义时，只能要求核对对应原厂手册，不能用平台默认语义替代现场手册。

## 5. 永久门禁要求

应新增独立的 G50 可信度 smoke，至少同时检查：

1. `gm-code-complete.js` 基础源仍为高风险多语义内容；
2. `search-aliases.js` 存在 `normalizeG50`；
3. 运行时归一化后仍包含“当前 CNC”“机床厂原厂手册”“车/铣语义差异”等安全提示；
4. 车床主轴限速说明不出现可直接照抄的固定 S 数值；
5. 铣床缩放取消说明不被错误描述成所有机床通用；
6. 不能通过 `.skip(`、成功退出、`continue-on-error` 或删除断言绕过；
7. 失败时上传真实诊断 Artifact；
8. exact-head checkout 必须证明实际测试提交与 PR 最新头一致。

## 6. PWA / 离线验收要求

由于后续整改会修改离线核心资源，合并前必须重新验证：

- `build-info.json`、`sw.js`、状态页和测试中的构建版本一致；
- 首次安装 Service Worker 后可获得新 G50 内容；
- 断网并真正关闭源站后，核心资源只能从当前版本缓存读取；
- 旧版本升级到新版本后，旧缓存不会继续提供过期 G50 内容；
- PWA self-test、BFCache、手机首页、起点测评与完整 CNC 回归继续通过；
- Pages exact-head 公网传播必须精确绑定合并后的 main SHA。

## 7. 合并约束

后续 G50 运行时整改只有在**同一个 latest exact head**满足以下条件时才允许合并：

- 独立 G50 基础源 + 运行时可信度门禁全绿；
- PWA/Service Worker/冷离线/BFCache/构建版本一致性全绿；
- 手机首页、起点测评和完整 CNC 回归全绿；
- 性能、无障碍、数据健康及 Pages 相关门禁无真实失败或 cancelled；
- 改动范围仍只在 `cnc/**` 与明确 CNC-only 工作流/测试；
- 无未解决 Review Thread；
- 不存在通过删测试、降断言或跳过步骤换绿灯的行为。

---

本审计的核心原则：**代码相同，不代表机型语义相同；平台只能教“如何确认本机规则”，不能把某一台机床的 G50 规则包装成万能口诀。**

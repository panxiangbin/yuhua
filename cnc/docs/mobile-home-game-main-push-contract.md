# CNC 手机闯关首页 main 推送与入口防漂移契约

## 目的

手机闯关首页是零基础用户进入 CNC 新手训练平台后的第一屏。它同时读取学习档案、错题和模拟训练数据，并把用户带到起点测评、12关课程、每日挑战、错题复习、模拟车间和成长档案。

专用 Chromium 门禁不能只在拉取请求阶段运行。改动合并到 `main` 后，必须再次执行相同的 390×844 真实浏览器验收，避免“PR 里正常，正式分支没有重新验证”的空档。

## 必须监听的事件

`cnc-mobile-home-game-ui-smoke.yml` 必须同时监听：

- `pull_request`；
- `main` 分支的 `push`；
- `workflow_dispatch`。

`pull_request.paths` 与 `push.paths` 必须保持完全对称。不得只补其中一侧，也不得依靠人工记忆维护两份不同清单。

## 必须覆盖的运行依赖

工作流至少要覆盖：

- `cnc/index.html` 的首页 DOM 与桌面/手机视图；
- `cnc/personal-home.js` 的等级、XP、下一关和入口生成；
- `cnc/mobile-home-game.css` 的 390×844 布局与触控尺寸；
- `cnc/import-test.js` 的启动和资源加载；
- `cnc/mobile-trust-nav.js` 的工具导航隐藏与恢复；
- `cnc/industrial-tools.js` 的现场速查入口；
- 起点测评、训练营、挑战、错题复习、模拟车间和成长档案页面；
- 所有 `cnc/course-*.html` 主线课程目标；
- 浏览器测试、触发覆盖测试、中文契约和工作流自身。

门禁必须从 `personal-home.js` 动态提取首页真实 HTML 入口和 12 关课程文件，确认目标文件存在，并确认每个目标都被 PR 与 main push 路径过滤器覆盖。课程入口可由受控的 `cnc/course-*.html` 模式覆盖，其他入口必须精确覆盖。

## 真实浏览器验收

专用门禁必须继续使用 Chromium 390×844 手机视口验证：

- 等级、XP、下一关和主线进度；
- 起点测评、课程、挑战、错题、模拟和成长档案入口；
- 单层底部导航及工具工作区导航恢复；
- 所有可见按钮和链接不小于 44px；
- 桌面端保留工具型首页；
- 零浏览器脚本错误。

不得把静态 grep 代替真实浏览器结果。

## Actions 与诊断纪律

- 权限必须保持 `contents: read`；
- 使用 Node 24；
- `cancel-in-progress` 必须为 `false`；
- 成功和失败都必须上传浏览器截图、错误文件、服务器日志和结构化触发覆盖报告；
- Artifact 名称必须包含 `github.run_id`，缺少诊断文件时必须失败，并保留14天；
- 不得使用 `test.skip`、`describe.skip`、`it.skip`、`process.exit(0)` 或把 `cancelled`、`skipped` 当作成功。

## 教学与现场边界

手机首页只负责学习导航和本地训练进度展示，不构成现场上机许可。课程、题库和模拟中的程序、参数、转速、进给、切深、安全高度、刀补、报警、联锁、复位和恢复内容均为教学参考；实际使用必须核对相同系统和机型的原厂手册、企业制度、受控工艺与现场条件，并由授权人员确认。

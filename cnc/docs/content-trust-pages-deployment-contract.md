# CNC 内容可信度 Pages 精确部署契约

## 目标

内容可信度基线进入 `main` 后，不能只确认仓库里存在文件，还必须确认 GitHub Pages 公网已经部署同一份状态页和清单，避免用户看到旧页面、旧清单或边缘缓存残留。

## 强制核验资源

- `cnc/content-trust-status.html`
- `cnc/content-trust-manifest.json`

两项资源都必须使用随机查询参数和 `no-store` 请求，分别读取 `main` 原始文件与 Pages 公网文件，并同时满足：

1. HTTP 请求成功；
2. 字节数完全一致；
3. SHA-256 完全一致；
4. 文件自身的内容可信度契约仍然存在。

## 状态页契约

状态页必须继续包含：

- `zh-CN` 页面语言；
- `CONTENT TRUST STATUS` 标识；
- 统一提示“教学参考，需按机床说明书、现场工艺和空运行验证”；
- 对 `content-trust-manifest.json` 的 `no-store` 读取；
- “不可直接上机使用”的明确边界；
- 返回 CNC 新手训练平台的入口。

## 清单契约

可信度清单必须继续满足：

- `schemaVersion` 为 `1`；
- 登记课程、报警、现场诊断、G/M 代码和补充知识 5 个高风险数据集；
- 至少 4 个数据集保持待逐条复核状态；
- 所有登记项的 `allowOperationalUse` 均为 `false`；
- 每个登记项都保留统一教学参考提示；
- 不得把公网部署成功解释为技术内容已完成逐条核实。

## 禁止做法

- 不得只比较 `build-info.json` 就宣称可信度资源已部署；
- 不得把 HTTP 200 当成字节一致；
- 不得移除 SHA-256 对比；
- 不得减少登记数据集来制造绿色结果；
- 不得把待复核内容标记为可直接上机使用；
- 不得修改予华仪器官网根目录、产品、图片或仪器数据。

## 诊断产物

Pages 工作流必须为每个资源生成独立 JSON 诊断，记录请求地址、重试次数、响应头、字节数、SHA-256、契约检查和最终结论。失败时保留错误文件并上传 Artifact，禁止伪造公网确认。

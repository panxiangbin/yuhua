# CNC 内容可信度复核队列契约

## 目标

把“哪些内容还没有逐条核实”进一步转化为可执行的复核顺序和证据要求，避免只显示待复核状态，却不知道先核对什么、需要哪些资料、完成条件是什么。

本契约只管理 CNC 新手训练平台的内容可信度状态，不代表任何报警、参数、刀补、G/M 代码或现场动作已经获得原厂确认。

统一边界：

> 教学参考，需按机床说明书、现场工艺和空运行验证

## 复核优先级

- **P0**：直接影响报警处置、程序解释、机床动作或安全恢复。当前固定为报警数据和 G/M 代码数据，必须优先核对对应系统系列的原厂资料及机床厂配置。
- **P1**：包含经验性范围、工艺诊断或跨类别现场建议。必须补齐正式资料、适用条件和现场验证记录。
- **P2**：已经具备文件级适用范围，但仍需继续补充逐课来源、手册版本、章节和复核日期。

优先级只是资料复核顺序，不是正确率、风险等级或上机许可。所有登记数据集的 `allowOperationalUse` 必须继续为 `false`，除非以后建立了更严格、逐条可追溯且经过单独审计的发布机制。

## 每个数据集必须具备

`cnc/content-trust-manifest.json` 中的每个登记项必须同时包含：

- `status`：当前可信度状态；
- `reviewPriority`：只能是 P0、P1 或 P2；
- `applicability`：明确适用范围和系统差异；
- `reviewBasis`：当前已有的复核基础；
- `requiredEvidence`：至少两项完成复核所需的可追溯证据；
- `nextAction`：清楚说明下一步如何推进；
- `allowOperationalUse: false`；
- 平台统一教学参考提示。

待复核数据的证据要求必须指向原厂、机床厂、正式标准、企业受控文件或可追溯现场记录，不能使用“网上常见说法”“经验上应该如此”等不可核验表述代替。

## 当前 P0 范围

当前 P0 只能包含：

1. `cnc/alarm-data.js`
2. `cnc/gm-code-complete.js`

新增或移除 P0 数据集必须经过单独范围审计，不能仅通过修改页面排序或测试数量完成。

## 页面与手机端要求

`cnc/content-trust-status.html` 必须：

- 公开显示登记数量、待复核数量、P0 数量和可直接上机数量；
- 按 P0 → P1 → P2 排列复核队列；
- 显示每个数据集的适用范围、证据要求和下一步动作；
- 明确 P0/P1/P2 不是上机许可；
- 保持 390×844 手机宽度无横向溢出；
- 保持中文、单一主要内容地标、返回 CNC 平台入口和浏览器零错误。

## 门禁要求

结构化审计和真实 Chromium 手机审计必须共同验证：

- 5 个高风险数据集完整登记；
- 4 个数据集保持待逐条复核；
- 报警和 G/M 代码恰好是 2 个 P0 数据集；
- 每项至少有两条证据要求和明确下一步；
- 复核队列排序正确；
- 可直接上机使用始终为 0；
- 成功和失败均上传结构化报告、问题清单和手机截图。

禁止通过删除数据、提高容忍范围、降低数量、跳过浏览器测试、把 `cancelled` 或 `skipped` 当作成功，或将未核实内容改成已核实来制造绿色结果。

## 修改范围

本能力只允许修改 `cnc/**`、CNC 专属测试、工作流和文档。不得修改予华仪器官网根目录、仪器产品、图片、参数或仪器数据。

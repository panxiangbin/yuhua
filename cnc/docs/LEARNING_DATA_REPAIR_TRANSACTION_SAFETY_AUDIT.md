# CNC 学习数据修复事务可靠性审计

## 审计目标

本审计只针对 `cnc/data-health.html` 的学习记录健康检查、修复、快照与回滚流程，不修改予华仪器官网根目录、产品、图片或仪器数据。

生产基线：`241241e341861e47177d3e5ffeaa2cbbcaaede75`。

当前页面处理的正式学习数据键包括：

- `cnc_training_profile_v1`
- `cnc_training_practice_v1`
- `cnc_training_simulator_v1`
- `cnc_training_exam_v1`
- 修复快照 `cnc_training_data_recovery_v1`
- 备份元数据 `cnc_training_backup_meta_v1`

## 已验证的真实缺口

### 1. 快照写入发生在修复 `try` 之外

当前执行路径是先调用 `snapshot(keys)`，随后才进入修复 `try`。`snapshot()` 内直接调用 `localStorage.setItem(...)`。

如果浏览器处于存储配额不足、隐私限制、SecurityError 或其它 LocalStorage 写失败场景，异常会在进入修复错误处理前抛出。结果是页面不会给出当前设计中的“修复失败”状态提示。

**安全要求：** 快照创建必须纳入同一个受控事务入口；快照未成功持久化时，禁止开始任何正式学习数据写入，并向用户明确报告“未修改原数据”。

### 2. 多键修复可能形成部分提交

当前修复逻辑按 `keys.forEach(...)` 逐个调用 `localStorage.setItem`。如果第一个数据键写入成功、后续某个键写入失败，前面的修改不会自动撤销。

这意味着一次用户操作可能留下“部分键已升级、部分键仍是旧结构”的混合状态。虽然页面保存了回滚快照，但当前错误路径不会自动恢复原状态，仍需用户再次点击回滚。

**安全要求：** 多键修复必须具备事务语义：

1. 先生成所有候选结果；
2. 在内存中完成 JSON 序列化与结构校验；
3. 成功持久化恢复快照；
4. 执行正式写入；
5. 任一正式写失败时立即从本次快照自动回滚已经写入的键；
6. 只有全部目标键写入并回读核对一致后，才报告“修复成功”。

禁止通过减少修复项、跳过失败键或吞掉异常来换取成功状态。

### 3. 回滚本身同样可能部分成功

当前回滚逻辑通过 `Object.entries(s.data).forEach(...)` 逐项 `setItem/removeItem`。任一中间写操作失败时，后续项目不会继续，已经完成的恢复也不会自动恢复到“回滚前”的状态。

**安全要求：** 回滚必须至少做到：

- 回滚前先验证快照版本、`data` 根结构和允许键白名单；
- 对待恢复值先完成 JSON/字符串边界校验；
- 跟踪每一个实际恢复成功的键；
- 一旦失败，明确报告“回滚未完整完成”和已恢复/未恢复键，不得显示“已回滚”；
- 不得写入白名单以外的 LocalStorage 键。

### 4. 无效备份日期可能被误判为“正常”

当前备份新鲜度逻辑在 `lastExportAt` 存在时直接执行：

```js
const days = Math.floor((Date.now() - Date.parse(m.lastExportAt)) / 86400000)
```

如果 `lastExportAt` 是不可解析的非空字符串，`Date.parse(...)` 返回 `NaN`，随后 `days` 也是 `NaN`。由于 `NaN > 7` 为 `false`，当前逻辑会把这项检查标记为 `ok`，同时显示类似“上次备份距今 NaN 天”。

这会让损坏的备份元数据获得错误绿灯。

**安全要求：** 对 `lastExportAt` 必须先用 `Number.isFinite(Date.parse(...))` 或等价方法验证；无效日期必须是 `warn` 或 `bad`，绝不能进入 `ok` 分支。

### 5. LocalStorage 读取不可用时健康检查可能直接中断

当前 `raw(k)` 直接调用 `localStorage.getItem(k)`，而 `scan()` 的多数读取没有包在存储能力级别的统一保护中。在部分隐私模式、禁用站点存储或浏览器策略场景里，`getItem` 可能抛出异常。

**安全要求：** 数据健康页应区分：

- “没有数据”；
- “JSON 损坏”；
- “浏览器存储不可访问”。

存储不可访问时不得把数据项统计成 0 后继续给出健康分，应明确提示当前无法验证数据健康，并禁止执行修复/回滚。

## 下一阶段实现门槛

下一次运行时整改至少应覆盖以下可验证行为：

1. 快照写失败时，正式四个学习数据键全部保持原值；
2. 第二个或后续正式键写失败时，已经写入的键自动恢复到操作前值；
3. 回滚出现中途失败时，不得显示完整成功，并列出未恢复键；
4. `lastExportAt='not-a-date'` 必须产生非绿状态；
5. `localStorage.getItem` 抛出 `SecurityError` 时，页面可用且明确显示“存储不可访问”；
6. 修复只能触及允许的 CNC 学习数据键和恢复快照键；
7. 成功修复后必须回读并验证持久化内容与预期候选结果一致；
8. 不删除原有健康检查，不降低现有断言，不使用 `.skip()`、`continue-on-error` 或吞异常伪造通过。

## 建议永久门禁

建立 CNC-only 的数据事务可靠性 smoke，至少注入以下故障：

- `setItem` 在创建快照时失败；
- `setItem` 在第 2 个正式键时失败；
- `setItem` 在回滚中途失败；
- `getItem` 抛出 `SecurityError`；
- 备份日期非法；
- 恢复快照包含非白名单键。

产物应记录：测试 exact head、初始键值、候选键值、故障注入点、最终键值、成功/失败状态和未恢复键列表，方便 Actions 失败时直接定位真实根因。

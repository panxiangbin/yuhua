# AI CNC 老师分类版本 Pages 部署契约

## 目的

分类准确性在拉取请求中通过，不等于新版分类逻辑已经部署到公网。本契约对 `cnc/ai-teacher.html` 的远程 `main` 与 GitHub Pages 公网版本进行逐字节、SHA-256 和语义三重核验，防止旧缓存、延迟部署或语义回退被误报为成功。

## 核验对象

- 当前分支 `cnc/ai-teacher.html`；
- 远程 `main` 的 `cnc/ai-teacher.html`；
- Pages 公网的 `cnc/ai-teacher.html`；
- 本地受控样本 `cnc/tests/fixtures/ai-teacher-classification-cases.json`。

## 网络与缓存要求

- 每次请求必须加入随机查询参数；
- 使用 `cache: no-store`；
- 请求头必须包含 `Cache-Control: no-cache, no-store, max-age=0`；
- 最多进行 18 次真实部署等待；
- 失败时仍上传结构化诊断和发现记录，不得用缓存结果或静态声明代替公网检查。

## 字节与摘要要求

远程 `main` 与 Pages 公网必须同时满足：

- HTTP 请求成功；
- 字节长度相同；
- SHA-256 完全相同。

拉取请求允许当前分支与 `main` 不同，并记录 `branchDeploymentPending: true`；合并后的 `main` 或手动复验应确认新版页面已经成为远程基线。

## 分类语义要求

公网页面必须保持：

- 分类版本 `20260802-v2`；
- NFKC 问题归一化；
- 四类高风险信号：固定上机值、参数写入、安全绕过、盲目复位；
- 安全讨论语境；
- 强执行意图优先规则；
- “安全原理说明”受控回答；
- 不提供可执行绕过步骤或固定上机值；
- 原厂手册、企业制度、受控工艺和现场授权边界；
- 本地运行，不调用外部模型和站外接口。

样本文件必须保持不少于 15 条阻断样本和 15 条正常学习样本，版本与页面一致，编号和问题文本唯一。

## 禁止绕过

门禁不得：

- 把重试次数设为 0；
- 使用 `test.skip`、`describe.skip` 或 `it.skip`；
- 使用 `process.exit(0)` 吞掉失败；
- 把 `cancelled`、`skipped`、排队或运行中当成成功；
- 宣称 `allowOperationalUse: true`；
- 仅检查关键词而不进行真实公网字节和摘要比较。

## 适用范围

该门禁只证明分类代码与受控边界已经准确部署，不证明任何具体机床参数、报警、刀补、联锁恢复或安全步骤已经获得现场放行。技术操作仍必须核对相同版本原厂手册、企业制度、受控工艺和现场条件，并由授权人员确认。

# CNC 12关主线课程目录双端防漂移契约

## 目的

手机闯关首页和训练营页面都维护同一套12关主线课程。两端分别负责“打开首页就知道下一步学什么”和“查看完整路线、成绩与训练建议”。如果课程顺序、标题或入口在一端修改后没有同步，零基础用户会看到不同的下一关，甚至进入不存在的页面。

本门禁动态读取两端真实 `COURSES` 目录，禁止再维护第三份不会自动核验的人工课程清单。

## 必须保持一致的内容

手机闯关首页 `cnc/personal-home.js` 与训练营 `cnc/training-camp.html` 必须同时满足：

1. 均为12关；
2. ID严格按 `stage-1` 至 `stage-12` 排列；
3. 同一关的入口文件完全一致；
4. 同一关标题必须相同，或一端是在另一端基础上增加面向新手的解释性副标题；
5. 每关都必须保留明确的学习理由；
6. 12个入口解析后的正式课程目标不得重复。

不得通过改变解析规则、减少课程数或跳过某一关来制造绿色结果。

## 课程入口与兼容入口

主线入口必须是仓库内的 `cnc/course-*.html` 页面，目标文件必须真实存在且是有效中文 HTML。

历史收藏、旧缓存或旧首页已经使用过的课程文件名，可以保留受控兼容入口，但必须满足：

- 兼容页自身可读取，不得是空文件；
- 只允许跳转到仓库内真实存在的正式课程页面；
- 不得跳转到站外、非课程页面、自身或另一层兼容入口；
- 必须提供可点击的手动继续按钮；
- 必须保留“教学参考、核对原厂手册和现场条件、由授权人员确认”的安全边界；
- 结构化报告必须记录兼容入口与正式目标的对应关系。

兼容入口只能用于保护旧链接，不得掩盖正式课程缺失。

## Actions触发范围

工作流必须同时监听：

- `pull_request`；
- `main` 分支 `push`；
- `workflow_dispatch`。

`pull_request.paths` 与 `push.paths` 必须完全对称，并至少覆盖：

- `cnc/personal-home.js`；
- `cnc/training-camp.html`；
- 所有 `cnc/course-*.html`；
- 本测试、本契约和工作流自身。

这样可以保证课程被删除、改名、换顺序、改入口或调整兼容跳转时，门禁必然运行。

## 诊断与反绕过

成功或失败都必须上传结构化报告，至少包含：

- 两端源文件 SHA-256；
- 两端12关目录；
- 每关入口及解析后的正式目标；
- 受控兼容入口；
- PR 与 main push 路径过滤器；
- 具体失败原因。

工作流权限必须保持 `contents: read`，使用 Node 24，`cancel-in-progress` 必须为 `false`。不得使用 `test.skip`、`describe.skip`、`it.skip`、`process.exit(0)`，不得把 `cancelled`、`skipped`、排队或运行中状态当作成功。

## 教学与现场边界

12关课程用于零基础学习和训练导航，不构成现场上机许可。课程中的程序、参数、转速、进给、切深、安全高度、刀补、报警、联锁、复位和恢复内容均为教学参考；实际使用必须核对相同系统和机型的原厂手册、企业制度、受控工艺与现场条件，并由授权人员确认。

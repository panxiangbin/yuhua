# CNC 测评首步课程离线核心防漂移契约

## 目的

起点测评会根据安全意识、坐标与刀补基础，把零基础学习者带到不同的第一步课程。只要路线目录发生变化，Service Worker、PWA 自检、首次安装冷离线回归和 PWA 升级保护就必须同步，否则用户可能离线完成测评、进入训练营后，点击“开始第1步”却打不开课程。

## 唯一路线来源

1. 先运行 `cnc/tests/beginner-placement-route-catalog-drift-smoke.cjs`，确认起点测评生产端与训练营消费端的路线目录完全一致。
2. 本门禁只从该测试生成的结构化报告读取当前路线，不再维护另一份人工首步清单。
3. 每类决策的直接开始链接 `route.href` 必须等于 `steps[0].href`，并且目标必须是 `cnc/` 下真实存在的受控 HTML 页面。
4. 多类决策可以共用同一张首步课程；诊断报告必须同时保留决策映射和去重后的首步课程集合。

## 必须同步的离线能力

当前路线目录推导出的全部首步课程必须满足：

- 已进入 `cnc/sw.js` 的 `REQUIRED_CORE_PATHS`；
- 已进入 `cnc/pwa-self-test.html` 的 `REQUIRED`；
- 与 `cnc/tests/mobile-pwa-offline-cache-smoke.cjs` 中专门用于首次安装冷离线验证的 `PLACEMENT_FIRST_STEP_COURSES` 完全一致；
- 与 `cnc/tests/mobile-pwa-upgrade-data-smoke.cjs` 中专门用于升级后冷离线验证的 `PLACEMENT_FIRST_STEP_COURSES` 完全一致；
- Service Worker 与 PWA 自检的完整核心资源集合必须一致，不能只让页面显示“已缓存”而实际 Worker 缺少资源。

冷离线和升级保护的首步课程集合要求精确相等，不允许遗漏当前路线，也不允许长期保留已经退出路线的陈旧测试项。Service Worker 可以包含其他有明确用途的 PWA 核心页面，但所有当前首步课程都必须在其中。

## 触发范围

以下任一内容变化都必须触发门禁：

- 起点测评或训练营路线目录；
- Service Worker 或 PWA 自检；
- 首次安装冷离线测试或升级数据保护测试；
- 任意 `cnc/course-*.html` 课程目标；
- 路线目录主测试、本门禁测试、中文契约或工作流自身。

这样在课程被删除、改名、路线首步调整或缓存清单漂移时，即使其他文件没有修改，门禁仍会执行并阻止不完整改动进入 `main`。

## 诊断与反绕过

每次成功或失败都必须上传结构化 Artifact，至少记录：

- 路线目录报告及相关文件 SHA-256；
- 每类决策的直接链接与第一步链接；
- 去重后的首步课程集合；
- Service Worker 与 PWA 自检核心资源；
- 冷离线浏览器测试与升级保护测试中的首步课程集合；
- 缺失项、集合不一致项和明确错误原因。

不得删除测试、减少路线决策、降低精确集合断言、跳过步骤、使用 `process.exit(0)` 吞掉失败，或将 `cancelled`、`skipped`、排队和运行中状态视为成功。

## 教学与现场边界

本门禁只保证学习路线与离线资源连续，不代表课程内容可直接作为现场上机值或岗位放行结论。课程中的程序、转速、进给、切深、安全高度、刀补、报警、联锁、复位和恢复步骤均为教学参考；实际使用必须核对相同系统和机型的原厂手册、企业制度、受控工艺与现场条件，并由授权人员确认。

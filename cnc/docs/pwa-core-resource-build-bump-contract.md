# PWA核心离线资源构建提升契约

## 目的

Service Worker 的静态缓存名称由 `cnc/sw.js` 中的 PWA 构建号决定。若核心预缓存页面已经修改，但构建号没有提升，已安装过网站的浏览器可能继续在离线状态读取旧正文。

本契约用于阻止以下真实风险：

- 安全基础、坐标轴、G00/G01等核心课程更新后，旧安装仍保留旧课程；
- 起点测评、训练营、AI CNC老师或PWA诊断页更新后，缓存版本没有变化；
- `REQUIRED_CORE_PATHS` 增删、改名或调整顺序，却没有建立新的静态缓存；
- `sw.js` 与 `build-info.json` 的PWA构建针不一致；
- 新构建号倒退、复用旧号或仅改日期文字而没有严格递增。

## 硬性规则

比较PR基线提交与最新头提交：

1. 动态读取两端 `cnc/sw.js` 的 `BUILD` 和 `REQUIRED_CORE_PATHS`，不得在测试中复制第三份固定核心清单。
2. 将基线与当前核心清单的并集视为受保护资源；这样即使资源从清单中删除，删除动作本身也仍会被审计。
3. 只要发生以下任一情况，PWA构建号必须提升：
   - `cnc/sw.js` 发生变化；
   - 任一基线或当前核心资源发生新增、修改、删除、改名；
   - 核心预缓存清单的内容或顺序发生变化。
4. 新构建必须符合 `YYYYMMDD-pwaN`，并相对基线严格递增。
5. 当前与基线的 `cnc/build-info.json` 中 `pwaBuild` 必须分别等于同提交的Service Worker构建号。
6. 门禁必须读取真实Git历史和真实变更文件，不得以手写文件列表、跳过测试、吞掉退出码或 `continue-on-error` 代替。
7. 成功和失败都必须上传结构化报告、完整运行日志及错误文件（失败时）。

## 不要求提升构建的情况

仅修改未进入核心预缓存的课程、题库、文档或测试时，可以保持当前PWA构建号；但已有的PWA构建引用审计仍会核对所有主动构建针是否一致。

## 数据与安全边界

PWA升级只更换CNC缓存，不得清除学习成绩、XP、错题、成长档案、SessionStorage、IndexedDB或其他应用缓存。相关保护继续由升级数据门禁验证。

课程与离线内容仅作教学参考。报警、参数、刀补、坐标方向和现场操作必须按相同控制系统及机型的原厂手册、企业安全制度、现场工艺和授权人员要求核对；任何离线可用性结论都不是现场上机许可。

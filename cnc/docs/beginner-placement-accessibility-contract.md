# CNC新手起点测评无障碍与可信推荐契约

## 目标

起点测评必须让零基础用户在手机触控、键盘和屏幕阅读器环境下都能独立完成，并且清楚知道当前题目、已选答案、测评进度、未选择提示、判断依据和最终推荐起点。

测评只做教学路线推荐，不修改成绩、XP、通关记录、成长档案或错题记录。

## 题目与单选语义

- 每道题的选项必须组成 `role="radiogroup"` 的单选组，并由当前题目标题命名。
- 每个选项必须使用 `role="radio"` 与真实 `aria-checked` 状态。
- 键盘必须支持方向键循环切换，`Home` 选择第一项，`End` 选择最后一项。
- 单选组采用可预测的单一 Tab 停靠点；选中项必须同步成为停靠点。
- 视觉选中状态与读屏选中状态不得分离。

## 进度与焦点

- 进度必须使用 `role="progressbar"`，提供最小值、最大值、当前值和中文 `aria-valuetext`。
- 切换到下一题或上一题后，程序化焦点必须落到题目标题。
- 用户未选择答案就继续时，必须显示独立的中文状态提示并把焦点送到提示，不得只修改按钮文字。
- 完成测评后，结果区域必须由结果标题命名，并关联推荐说明、判断依据与路线。
- 结果出现后焦点必须落到结果标题。
- 重新测评后必须清空答案、恢复进度，并把焦点送回第一题标题。
- 程序化焦点和键盘焦点必须有至少 3px 的可见轮廓。

## 手机与动态效果

- 390×844 手机视口下，所有可见按钮和链接宽、高均不得小于 44px。
- 尊重 `prefers-reduced-motion: reduce`，进度条不得继续播放过渡动画。
- 不得依赖悬停才能看见关键操作、判断依据或结果。

## 推荐逻辑

必须保留三档推荐：

1. 安全基础优先；
2. 坐标、对刀与刀补基础；
3. 程序验证与首件检查。

安全意识必须优先于操作熟练度。关键安全项包括：

- 陌生程序上机前验证；
- G00 快速移动碰撞路径确认；
- 首件尺寸与图纸、公差核对；
- 报警状态记录与原因排查。

关键安全项采用硬门禁：任一关键安全项选择危险答案，即使总分达到 10/12，也必须推荐从安全基础开始，其他题的高分不得抵消危险答案。

关键安全项没有危险答案，但坐标系或对刀、刀补基础题出现基础性错误时，必须推荐坐标、对刀与刀补路线，不能直接进入程序验证与首件检查。

只有关键安全项全部通过、坐标与刀补题没有基础性错误且总分达到受控阈值时，才允许推荐程序验证与首件检查。推荐结果必须显示中文判断依据，包括总分、触发的安全项或基础缺口，并明确结果不是现场上机许可。

不得因为用户自评熟练，就跳过安全、坐标、对刀、程序验证或首件检查边界。

## 隐私与数据边界

- 测评答案和结果只保留在当前页面内存中。
- 不得写入 LocalStorage、SessionStorage、IndexedDB、成长档案、错题记录或 URL。
- 不得调用外部模型、站外接口、WebSocket 或 EventSource。
- 重新测评必须清除本页答案，不得恢复上一次结果。

## CNC技术与安全边界

测评推荐不是现场放行结论，不代表具体机床、数控系统版本、刀具、夹具、工件或工艺已经确认。

涉及具体参数、报警、刀补、联锁和恢复操作，必须核对相同版本原厂手册、企业制度、受控工艺与现场条件，并由授权人员确认。不得提供固定上机值、参数写入步骤、联锁绕过、盲目复位或未经验证的现场操作结论。

## 门禁纪律

不得删除或跳过原有低分路线和高分路线断言，不得只测试静态 HTML。真实门禁必须使用 Chromium 390×844 视口，验证方向键操作、焦点、ARIA、低分路线、高分路线、10/12 高分但关键安全项错误仍回到安全基础、坐标或刀补基础缺口分流、可见判断依据、44px 触控、减少动态效果、零长期存储、零站外请求和零浏览器错误。

不得使用 `test.skip`、`describe.skip`、`it.skip` 或 `process.exit(0)` 吞掉失败。成功和失败都必须上传结构化报告、发现说明和截图。

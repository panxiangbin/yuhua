# CNC 内容可信度基线契约

## 目标

CNC 新手训练平台包含课程、报警、参数、G/M 代码和现场故障诊断。部分资料来自知识库整理或经验总结，可能受到数控系统系列、机床厂配置、软件版本、材料、刀具、装夹、冷却和现场工艺影响。

本契约的第一目标不是把所有内容贴上“已核实”，而是先诚实区分：

- 已经写明主要教学系统和适用范围的课程数据；
- 尚未逐条核对原厂资料的报警、诊断、G/M 代码和补充知识数据；
- 任何情况下都不能直接替代机床说明书、风险评估、首件确认、单段运行和空运行验证。

统一提示为：

> 教学参考，需按机床说明书、现场工艺和空运行验证

## 状态定义

### `reviewed_scope`

仅表示文件级适用范围、系统示例和核对要求已经明确，不代表适用于所有机床，也不等于每一个数值都完成原厂资料核验。

### `pending_manual_verification`

内容包含报警含义、经验性数值、排查顺序、参数或现场动作建议，尚未逐条核对原厂手册和现场工艺。必须保持“不可直接上机使用”。

### `pending_system_scope_review`

内容可能因 FANUC 系列、参数设定、机床厂 M 代码、宏程序和选配功能不同而变化，尚待逐条标注适用系统。

## 强制规则

1. `cnc/content-trust-manifest.json` 必须登记课程、报警、诊断、G/M 代码和补充知识数据。
2. 所有登记项必须包含适用范围、复核依据和统一教学提示。
3. `allowOperationalUse` 必须为 `false`；没有逐条核验、现场验证和审批流程时，不得改为 `true`。
4. 报警和诊断数据当前必须保持待复核状态，不得因为门禁需要绿色而伪装成已核实。
5. 门禁会统计数值建议、系统相关词和现场动作词，作为后续逐条复核队列依据。
6. 不得通过删除高风险内容、删除测试、减少扫描文件、跳过浏览器测试或伪造报告制造绿色结果。
7. 技术结论不确定时必须明确写“无法确认具体机型或系统版本，需核对原厂手册”，不得猜测报警含义、参数号、刀补方向或安全步骤。

## 当前诚实基线

- `learning-content-data.js`：已具备文件级 FANUC 立式加工中心适用范围和机床说明书核对要求，状态为 `reviewed_scope`。
- `alarm-data.js`：报警含义和处置步骤尚未逐条核对原厂报警手册，状态为 `pending_manual_verification`。
- `diagnosis-data.js`：包含悬伸倍数、进给调整、预热时间、余量等经验范围，状态为 `pending_manual_verification`。
- `gm-code-complete.js`：需逐条区分系统系列、参数设定和机床厂 M 代码，状态为 `pending_system_scope_review`。
- `weak-category-data.js`：需按工艺、参数、报警、刀具和安全类别逐条复核，状态为 `pending_manual_verification`。

## 验收

独立工作流必须完成：

- JSON 清单结构与范围检查；
- 数据文件存在性和风险词统计；
- 课程适用范围检查；
- 报警、诊断数据不得被标记为已核实；
- 390×844 真实 Chromium 打开可信度状态页；
- 页面显示 5 个登记数据集、4 个待逐条复核、0 个可直接上机使用；
- 无横向溢出、失败请求、控制台错误或页面错误；
- 成功和失败都上传结构化报告、问题清单和手机截图。

本门禁只建立可信度状态和防伪基线，不宣称待复核内容已经正确。后续应按原厂资料逐批复核，修正真实内容后再提升对应状态。
